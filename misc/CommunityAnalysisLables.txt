Short answer: it's reasonable as a first-pass heuristic, but it would not stand up to serious network science scrutiny without refinement.
 
The biggest issue isn't the code. It's that the labels imply structural properties that the metrics don't actually prove.

What works well

You're trying to classify communities using interpretable metrics:

Size
Connectivity (avg_degree)
Isolation fraction (isolated_pct)
Engagement (avg_repost_count)

That's much better than arbitrary cluster numbering.

The hierarchy also makes intuitive sense:

Peripheral
Core Hub
Large Community
Active Circle
Tight Cluster
Engaged Micro-Group
Discussion Group


A human analyst can understand those labels immediately.

Problem 1: "Peripheral" is probably too aggressive

You define:

isolated_pct >= 0.5 ~ "Peripheral"


Imagine:

size = 100
50 isolated nodes
50 highly interconnected nodes


This community might actually contain a strong active core.

Yet you're classifying it as:

Peripheral


solely because half the members are disconnected.

In social networks this situation is common:

many lurkers
few active participants

The community is not necessarily peripheral.

A better interpretation might be:

Sparse Community
Dormant Community
Inactive Community


rather than "Peripheral."

Problem 2: Average degree is dangerous

You use:

avg_degree > med_degree * 1.5


The mean degree can be misleading.

Example:

99 nodes degree = 1
1 node degree = 100


Average degree becomes elevated.

The community looks "hub-like" even though almost everyone is disconnected from everyone else except one central account.

This creates false "Core Hub" classifications.

I'd trust:

median_degree


or

density


more than average degree.

Problem 3: Core Hub is not actually measuring a hub

You define:

size >= 50 &
avg_degree > med_degree * 1.5


This doesn't identify a hub.

In network science a hub usually means:

Highly central node(s)


using measures such as:

degree centrality
betweenness
eigenvector centrality
PageRank

Your metric identifies:

Large + highly connected


which is closer to:

Dense Large Community


than:

Core Hub


The label overclaims what the metric proves.

Problem 4: No density measure

This is probably the biggest omission.

Communities can have identical average degree and totally different structures.

Community A
100 nodes
each node connected to 50 others


Very dense.

Community B
100 nodes
50 nodes isolated
50 nodes fully connected


Same average degree is entirely possible.

Very different structures.

A density metric would separate them immediately.

For communities, density is often more informative than average degree.

Problem 5: Size dominates everything

Consider:

size >= 50 ~ "Large Community"


This catches everything not already classified.

Suppose:

size = 400
avg_degree = 1
isolated_pct = 0.2


This becomes:

Large Community


even though it may actually be a weakly connected collection of users.

Size overwhelms structure.

Problem 6: "Active Circle" vs "Tight Cluster"

You have:

size >= 20 & avg_degree >= med_degree ~ "Active Circle"

size >= 10 & avg_degree > med_degree ~ "Tight Cluster"


These categories are mostly size buckets.

The connectivity criteria are nearly identical.

So:

19 nodes
avg_degree = 20


becomes:

Tight Cluster


while

20 nodes
avg_degree = 20


becomes:

Active Circle


A one-node difference changes the label.

That suggests the distinction isn't very meaningful.

Problem 7: Engagement mixed with structure

This rule:

size < 10 &
avg_repost_count > q75_repost


is measuring behaviour rather than topology.

Everything else is:

network structure


but suddenly:

repost activity


enters the classification.

So your taxonomy mixes:

Structural properties
size
connectivity
isolation

with

Behavioural properties
reposting

Those are really different dimensions.

A community could be:

Tight Cluster + High Engagement


rather than being forced into one category.

If I were reviewing this professionally

I'd say the framework is:

Good for descriptive reporting. Weak for scientific classification.

A more defensible approach would be:

Structural type

Based on:

Size
Density
Isolation rate
Modularity
Centralization


Examples:

Core
Peripheral
Dense Cluster
Sparse Cluster
Fragmented
Bridge Community

Engagement type

Based on:

Posts
Replies
Reposts
Growth


Examples:

High Engagement
Moderate Engagement
Low Engagement


Then communities have two labels:

Dense Cluster + High Engagement

Sparse Community + Low Engagement

Core Community + Moderate Engagement


which is much more analytically robust.

Overall verdict

I'd give the current algorithm about 6.5/10.

Strengths

Easy to explain
Easy to implement
Produces intuitive labels
Good for dashboards

Weaknesses

Average degree is a fragile measure
"Core Hub" is not actually identifying hubs
"Peripheral" is too heavily driven by isolated nodes
No density or centralization measures
Structural and behavioural metrics are mixed together
Some category boundaries are arbitrary (20 vs 19 nodes)

For a Bluesky-style social graph, I'd strongly consider replacing avg_degree with community density and adding some measure of centralization. Those two changes alone would make the classification substantially more defensible.
